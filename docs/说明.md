# 节点生成与 Agent 阶段契约

## 骨架生成

默认编剧流程先按节点预算、结局数量和分支参数生成完整拓扑。节点编号、类型、出口、出口去向和汇合点由模板确定。模板校验通过后，编剧模型按批填写标题、梗概和选项文案，并可在首批补充角色设定。下一批接收前情提要。

批次目标为 20 个节点。每批首次调用失败后最多重试两次，之后保留该批模板文案。有效的部分回复会直接合入，遗漏字段保留占位内容，重复、批外引用和多余的结构字段会被忽略。处理情况写入 `meta.structure_warnings`。冻结的骨架和已完成节点随检查点保存，恢复时从剩余对白继续。正常的离线模式和显式旧版按章流程仍可使用。

## 阶段交接

| 阶段 | 消费 | 产出 | 验收 |
| --- | --- | --- | --- |
| writer | 用户需求、项目参数、角色资料 | 节点和连线、对白、背景描述、角色、排产表 | 首节点为唯一入口，全部可达，无环、无断头，至少一个真结局，排产表完整 |
| art | 剧本中的背景键、角色和姿态、排产表 | 背景、基底和差分立绘、风格，已有界面素材 | 同一背景键只引用一张图，立绘和已登记界面素材可用，识别占位 |
| voice | 对白和配音批次 | 音频路径和时长 | 音频文件可读，时长与文件一致，静音占位单独计数 |
| build | 编剧、美术、配音的交付 | 校验后的可导出图 | 全图结构和素材引用通过校验。关闭自动配音时接受 `voice=off` |
| review | 装配结果和各阶段验收记录 | 汇总质检报告 | 检查报告和结论是否已保存。关闭最终质检时记录 `off` |

阶段状态和验收结果持久化到 `agent_state.pipeline`。下游在开始前读取依赖的状态和影响。`real` 表示产出通过验收，`mock` 表示已有可用产出且含占位或推导内容。`failed` 会中止流水线，失败阶段可从已保存的进度重试。

背景和立绘可能同时含真图与占位。语音失败的句子可用按字数估时的静音文件补齐。下游直接使用已经落盘的内容，状态和具体影响会写到完成事件及导出的 `export_report.json`。Web 与 Ren'Py 的报告在导出目录，Unity 的报告在生成的可执行文件旁。

美术和配音只依赖编剧交付，任务上可以并行。目前两者顺序执行，共享的 `AgentTools` 会替换并保存整图。并行执行需要分别提交素材补丁，再由单一写入方合并，避免两份图互相覆盖。

## 失败与重试

- 骨架文案按批重试；台词按内容校验重试，仍缺失的节点走本地填充。已完成节点可复用。
- 供应商不可用时使用已有备用通道或已落盘的占位内容。单张参考图错误可只降级受影响的素材。
- 结构、文件引用或阶段验收失败时中止并记录失败代码。修复后从检查点恢复，后续阶段重新验证依赖。
