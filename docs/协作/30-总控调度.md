# 总控：怎么调度这四个 Agent

> 经理（DSH 里的助手）写这份。主人在四个外部工具里各粘贴一份提示词，
> 它们改完文件后，经理读 `docs\handoff\*.md` 做融合、验收、提交。

---

## 一、分工

| 谁 | 领域 | 一句话任务 | 产出落点 |
|---|---|---|---|
| **Kimi** | 前端 `ui\**` | 参考图上传、语音标注、素材库面板、导出页加 Unity | `docs\handoff\kimi.md` |
| **Astra** | 后端 `app\**` | TTS 时长修复、参考图/语音上传接口、生图带参考图、抠图、素材库接口 | `docs\handoff\astra.md` |
| **Grok** | 缝 `engine\export_*` + `tools\` | 把「出 .exe」变成一次函数调用 | `docs\handoff\grok.md` |
| **WorkBuddy** | 只读 | 跑回归 + 截图 + 报告目录 | `docs\handoff\workbuddy.md` |
| **经理** | `contract.py`、`mock_api.py` 接线、git | 定契约、融合、验收、提交 | 最终交付 |

---

## 二、调度顺序（重要，别乱开）

### 第一波：可以同时开（文件边界不重叠）

- **Astra**（后端）—— 活儿最多，最先开
- **Grok**（缝）—— 完全独立，可以同时
- **WorkBuddy**（跑腿）—— 只读，随时可以，但它拍的是**当前状态**

### 第二波：Kimi（前端）

**技术上可以和 Astra 同时开**（`ui\` vs `app\` 不重叠），前提是 Kimi 能接受
「后端接口还没好，我先对着契约写 UI + 假数据」。

如果 Kimi 非要等后端 —— 那就等 Astra 交活后再开。

### 第三波：经理融合

四个 handoff 回来后：
1. 读四份 handoff
2. `git diff` 看每个人到底改了什么（**主要看有没有越界**）
3. 我在 `mock_api.py` 里接 Unity 导出那根线（谁都别碰那几行）
4. 跑全套回归
5. 端到端真跑一次（上传参考图 → 生成 → 导出 exe）
6. `git commit` 分人的提交，出错能单独回滚

---

## 三、为什么能并行（文件边界）

```
Kimi   → ui\**                          独占
Astra  → app\**  (除 contract / export_*) 独占
Grok   → app\engine\export_*.py + tools\ + D:\UnityProject   独占
经理   → app\contract.py + mock_api.py 的 export 接线 + git
```

**唯一的共享热点是 `app\mock_api.py`** —— 所以规定：Astra 可以加新路由文件
和改 `main.py`，但**不许动 export 函数**；Grok 完全不碰；接线留给经理。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 没有 git 时并行改文件没法回退 | **已建 git 基线**（commit `c079635`），融合时分人提交 |
| 两人改同一文件 | 文件边界表 + `git diff` 检查越界 |
| 外部 Agent 看不到彼此的上下文 | 每份提示词自包含；细节在 `docs\协作\*.md`；交接只认 handoff 文件 |
| 它们说"改好了"但其实没跑 | 判罚标准：写了"应该没问题"的一律按没验证打回 |
| 后端抢先改坏了基线 | 每人事先约定回归命令，交活时贴输出 |
| Grok 构建 Unity 几十分钟，超时 | 提示词里给了"超时+日志落文件"，别用 capture_output |
| 磁盘只剩 25 GB | 已写进 Grok 任务书，产物用完清理 |

---

## 五、经理的融合清单（四个都交回后照这个走）

1. `git status` / `git diff --stat` —— 看谁改了什么，有没有越界
2. 越界了 → 让那人重来（或我手工剥离），**不许将就**
3. 接线：`app\mock_api.py`
   - `class Export` 的 `Literal` 加 `'unity'`
   - export 函数里加 `elif body.format == 'unity':` 调 `export_unity_and_build`
4. 契约要加字段（如角色 `poses` 差分）→ 我在 `contract.py` 改，加默认值
5. 跑全套回归（6 项 + TTS 探针 + 上传探针）
6. 端到端：起后端 → 新建项目 → 传参考图 → 生成 → 导出 unity → exe 能开
7. `git commit`：按人分开提交（`feat(front): kimi 上传UI` / `feat(api): astra 上传接口` …）
8. 更新 `HANDOFF.md` + MEMO
