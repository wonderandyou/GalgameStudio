# 接口契约 v1（Kimi 与 Astra 共同遵守）

> 定这份契约的是经理。**任何一方觉得不对，不要自己改形状** —— 写进 handoff，经理统一改。
> 现有接口风格参考 `app/mock_api.py`：成功返回 dict，失败抛 `ProviderError(code, message, where, status)`，
> 全局异常处理器会转成 `{"error": {"code", "message", "where", "field"?}}`。

---

## 0. 通用约定

- 前缀：所有接口都在 `/api` 下（router 已带 `prefix='/api'`）
- `{pid}` = 项目 id，形如 `p_63b2b758e0ab46d1bf4201629468eb36`
- 错误：HTTP 4xx/5xx + `{"error": {...}}`，**不要返回 200 里套 error**
- 文件落盘用项目相对路径（如 `assets/ref/character-a1b2.png`），对外访问统一走
  已有的 `GET /api/assets/{pid}/{asset_path:path}`
- 时间戳：ISO 字符串（`datetime.now(timezone.utc).isoformat()`）

## 1. 参考图

### 1.1 上传

```
POST /api/projects/{pid}/references
Content-Type: multipart/form-data
  file   : 图片文件（PNG / JPEG），≤ 20 MB
  kind   : "character" | "scene"        角色立绘参考 / 场景风格参考
  label  : 可选，显示名，默认取原文件名（不含扩展名）
```

成功 200：

```json
{
  "ok": true,
  "reference": {
    "id": "ref_7f3a2c",
    "kind": "character",
    "label": "女主-原始立绘",
    "asset": "assets/ref/character-9c1e4b2a7d0f3e58.png",
    "width": 1024, "height": 1536,
    "bytes": 842113,
    "sha256": "9c1e4b2a7d0f3e58...",
    "created_at": "2026-11-07T12:00:00+00:00"
  }
}
```

- 落盘：`projects/{pid}/assets/ref/{kind}-{sha256前16位}.{扩展名}`（内容寻址，重复上传同一张不重复写）
- 登记：`projects/{pid}/refs.json`，结构 `{"version": 1, "items": [ ...上面 reference 的形态... ]}`
- 校验：不是 PNG/JPEG 魔数 → `INVALID_IMAGE 422`；超过 20 MB → `FILE_TOO_LARGE 413`
- `kind` 不在枚举内 → `INVALID_KIND 422`

### 1.2 列表

```
GET /api/projects/{pid}/references
```

```json
{"ok": true, "references": [ ...同上的 reference 对象... ], "count": 2}
```

项目还没有 `refs.json` 时返回空数组，**不要报错**。

### 1.3 删除

```
DELETE /api/projects/{pid}/references/{ref_id}
```

```json
{"ok": true, "deleted_id": "ref_7f3a2c", "note": "只删登记，磁盘文件保留"}
```

**只删登记、不删磁盘文件** —— 同一个 sha 可能被别的角色/项目引用。

## 2. 语音素材

### 2.1 上传

```
POST /api/projects/{pid}/voices
Content-Type: multipart/form-data
  file         : 音频（wav / mp3 / ogg / m4a），≤ 20 MB
  character_id : 可选，标注这段语音属于哪个角色（对应 graph.characters[].id）
  label        : 可选，显示名
```

成功 200：

```json
{
  "ok": true,
  "voice": {
    "id": "voi_1b9d4e",
    "character_id": "heroine",
    "label": "女主-温柔",
    "asset": "assets/voice/4d2c8f0a1b3e5d79.wav",
    "seconds": 2.64,
    "bytes": 126764,
    "sha256": "4d2c8f0a1b3e5d79...",
    "created_at": "2026-11-07T12:00:00+00:00"
  }
}
```

- 落盘：`projects/{pid}/assets/voice/{sha256前16位}.wav`
- 登记：`projects/{pid}/voices.json`
- **非 wav 必须转成 wav**（24 kHz / 16 bit / mono，和 TTS 输出同规格）。
  本机可用 `ffmpeg`（若没有，直接拒绝非 wav 并返回 `NEED_WAV 415`，不要静默改名）
- **`seconds` 必须写真实时长**，且**不能信任 wav 头里的 data chunk 大小**
  （流式 wav 的头是占位值，踩过：声明 2147483547 字节、真实 126720 字节）。
  算法：`seconds = (文件字节数 - 44) / (采样率 × 声道 × 位深/8)`，或用
  `wave` 读参数 + 自己按实际剩余字节算。

### 2.2 列表 / 删除

```
GET    /api/projects/{pid}/voices        → {"ok": true, "voices": [...], "count": 1}
DELETE /api/projects/{pid}/voices/{id}   → {"ok": true, "deleted_id": "..."}
```

## 3. 素材库总列表

```
GET /api/projects/{pid}/library
```

```json
{
  "ok": true,
  "background": [{"name": "bg/xxx.png", "asset": "assets/bg/xxx.png", "bytes": 123, "mtime": "..."}],
  "character":  [{"name": "char/xxx.png", "asset": "assets/char/xxx.png", ...}],
  "reference":  [{"name": "ref/xxx.png", "asset": "assets/ref/xxx.png", ...}],
  "voice":      [{"name": "voice/xxx.wav", "asset": "assets/voice/xxx.wav", ...}]
}
```

扫 `assets/{bg,char,ref,voice}/` 下真实存在的文件，**不要读 json 登记表**
（磁盘才是真相，登记表可能和磁盘不一致）。


响应沿用现有形状：`{"ok": true, "job_id": ..., "out": "...", "warnings": [...]}`

## 6. 字段为什么这么定（给两边的理由）

- **`asset` 存项目相对路径、不存绝对路径**：项目可搬走，绝对路径一搬就废
- **内容寻址（sha16）当文件名**：重复上传不重复占盘，且天然去重
- **上传后返回完整对象、不返回裸 id**：前端不用再请求一次
- **`kind` 只分 character / scene**：对应「角色立绘参考」和「场景风格参考」两类，
  不要加第三类 —— 加之前先问经理
- **参考图不进 `assets/bg` 或 `assets/char`**：那两个目录是**生成产物**，
  参考图是**输入**，混在一起会让「素材库按 bg_key 复用」逻辑错乱
