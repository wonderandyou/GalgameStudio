## 项目

## 现状

**问题：画布是平铺的，节点一多就没法用**

现在「剧情编排」页把整张图的所有节点摊在一个 LiteGraph 画布上。
后端正在改成能生成 **700~1000 个节点**（一部 1~2 小时的 Galgame），
一屏上放一千个节点，肉眼找不到东西，拖一下就卡。

**问题：生成过程看不到进度**

后端 job 会通过 SSE 推事件，前端目前只显示一行日志文字。
一个千节点的生成要跑几十分钟，用户需要知道「现在写到第几章了」。

## 后端接口（已经存在，直接用）

### 生成任务

- `POST /api/projects/{id}/generate` → 返回 `{job_id}`
- `GET /api/jobs/{job_id}/events` → **SSE 流**，`ui/api.js:293` 已有封装参考
- `POST /api/jobs/{job_id}/cancel`

SSE 事件类型（`data` 是 JSON）：

| event | data |
|---|---|
| `agent` | `{agent, state, progress, msg}` — agent 是 `writer/art/voice/build`，state 是 `run/done/failed`，progress 是 0~1 |
| `node` | `{node_id, patch}` — 某个节点内容更新了 |
| `log` | `{level, text}` |
| `job` | `{state, progress, error?}` — 整个任务的状态 |

### 图数据

- `GET /api/projects/{id}/graph` — 完整图（`nodes[]` + `links[]`）
- `PUT /api/projects/{id}/graph` — 保存
- 节点结构见 `app/contract.py`（只读，别改后端）

> ⚠ 后端正在加「章节」这一层（幕 → 章 → 节点）。如果 `/graph` 响应里出现
> `chapters` 字段就按它分组；暂时没有的话，**前端要能在没有 chapters 时优雅降级**
> （全量显示，不报错）。

## 你的任务

### 任务 1：章节导航（核心）

在「剧情编排」页左侧（现有左侧面板区域）增加一个**章节树**：

```
▼ 第一幕 雨夜
   ✓ 01 天台相遇        14 节点
   ✓ 02 两年前的雨      16 节点
   ▶ 03 那张车票        写作中…
▼ 第二幕 离开
   ○ 04 车站            未开始
```

要求：

- 幕可折叠，章显示状态（未开始 / 写作中 / 已完成）和节点数
- 点某章 → **画布只显示这一章的节点**（其它章隐藏），视图自动适配缩放
- 有「显示全部」开关，切回全图
- 章节数据从 `/graph` 的 `chapters` 取；没有该字段时整个章节树隐藏，不影响现有功能

### 任务 2：生成进度面板

生成过程中在界面上显示：

- 当前哪个 Agent 在干活（编剧 / 美术 / 配音 / 装配）
- 当前章节 +「已写 128 / 目标 980 节点」
- 总体进度条
- 可取消

数据来自上面那张 SSE 事件表。注意 `agent` 事件的 `progress` 是**单阶段内**的进度，
总进度要自己按阶段权重算（编剧 60% / 美术 20% / 配音 15% / 装配 5% 起步，可调）。

### 任务 3：画布性能

一千个节点不能卡。至少做到：

- 进入某章视图时只渲染该章节点
- 缩放很小的时候不要逐节点画完整内容（具体做法你自己实测决定）
- 拖动画布、缩放时不掉帧

**必须实测**：造一个至少 800 节点的假数据（可以在浏览器里构造 JS 对象塞给
`GalEditor.load()`），测出实际帧率和操作延迟，把数字写进报告。
不要只说「优化了」。

### 任务 4：生成参数补充

「生成参数」区现在有节点数滑条和分支层数。后端新增了 `target_minutes`
（目标游玩时长，分钟，默认 60），加一个滑条：

- 范围 30~180 分钟
- 旁边实时显示换算后的预估节点数（公式：分钟 × 300 ÷ 48 × 1.3，取整）
- 提交给 `/generate` 时带上

> 注意：节点数上限会从 64 放开到 2000。现有滑条的上限和刻度要跟着改。
