# 背景：一个地点只画一张

---

## 一、按 `bg_key` 归并

编剧给每个节点写了 `bg_key`。同一个键 = 同一个地点 = **只生一张图**。

```
tenshou_rain     天台·雨      出现在 40 个节点  → 生 1 张
station_night    车站·夜      出现在 25 个节点  → 生 1 张
room_morning     房间·清晨    出现在 30 个节点  → 生 1 张
```

一部 1000 节点的作品，实际只需要 **15~30 张背景**。

### 顺序

```
1. list_pending_assets()             → 拿到按节点数排序的 bg_key 列表
2. 从多到少依次生成                   → 用得最多的先画，中途中断也不亏
3. 一个 bg_key 只调一次 generate_image
```

`generate_image` 内部会检查：同 key 已有图就跳过，不会重复烧额度。

---

## 二、先把位置和时间说清楚

背景是**三维归并**：地点 × 时间 × 天气。

`place / time / weather` 这三项写进 `bg` 对象，素材库靠它们判重 ——
「黄昏的天台」和「天台的黄昏」必须算同一张，靠散文描述做不到，靠这三个字段才行。

### 写法

```
place    老旧高中教学楼天台
time     深夜
weather  下雨
```

不要把它们混进一句散文里 —— 那样素材库判不出来，下次还会重画一张。

---

## 三、提示词只写客观事实

```
✓ 老旧的学校天台，水泥地，铁栏杆，晾衣杆。深夜，下雨，
  远处城市灯光被雨雾糊成一片暖橘色。地面有积水反光。

✗ 赛博朋克风格的绝美雨夜天台，氛围感拉满，电影级打光，8k 超清
```

第二种写法的问题：形容词堆砌，模型自由发挥，
40 个节点之间无法保持一致 —— 而且画风和风格圣经打架。

**画法、光影、色板由 `draft_prompt` 统一注入，你不要自己写。**

---

## 四、三条构图硬要求

1. **不允许出现人物。** 人物是叠上去的，背景画进去就再也去不掉。
2. **不允许出现文字、招牌字、水印。** 生图模型的文字基本都是错字。
3. **底部或一侧留出低信息区。** 对话框会盖住底部约 30%，
   关键物件不要放在那里。

---

## 五、复用优先

出图前先看素材库：

| 情况 | 做法 |
|---|---|
| 同地点 + 同时间 + 同天气 | 直接复用，一次额度都不花 |
| 同地点、不同时间 | 重新出（晨 / 昏 / 夜是三种光，不能共用） |
| 同地点、不同天气 | 重新出 |
| 近似但不完全相同 | **不要凑合**，重出 |

`generate_image` 会自动查库，命中时返回 `reused` 字段。

---

## 六、自检

- [ ] 每个 `bg_key` 只有一张图
- [ ] 图里没有人、没有文字
- [ ] `place / time / weather` 三项都填了
- [ ] 底部 30% 没有关键物件
- [ ] 同 key 的图在不同节点里是同一张（没有混进第二张）
