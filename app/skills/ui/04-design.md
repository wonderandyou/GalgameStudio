# 按用户要求设计界面：`design_ui` 怎么用

`render_ui` 是从四套现成预设里**挑**；`design_ui` 是按用户的**具体要求生成**一套新的。
这一篇讲什么时候用它、输入怎么给、出来的东西是什么。

---

## 什么时候用

| 用户的说法 | 用哪个 |
|---|---|
| 「要水墨风」「要冷色剧场那种」—— 给的是一个**流派** | `match_ui_preset` + `render_ui` |
| 「标题要大一点，字距拉开，暗红强调色」—— 给的是**具体参数** | `design_ui` |
| 附了**参考图**，说「照这个感觉来」 | `design_ui`（参考图传 `reference_images`） |
| 什么都没说 | `match_ui_preset` 按题材挑，别硬设计 |

**判断标准一句话**：用户说的是**流派名**就挑预设；说的是**具体效果**或给了**参考图**，才设计。

---

## 输入怎么给

### `requirement`

**原样传用户的话，一个字都不要改。** 不要总结、不要扩写、不要翻译成英文。

- ✓ `"江南雨夜，水墨留白，安静克制；标题要大，字距拉开，不要立绘"`
- ✗ `"中国风、宁静、文艺风格"` ← 这是你自己改写过的，用户具体要的那个「大标题」丢了

内部会解析这些词（都是硬开关，会真的落到参数上）：

| 要求里出现 | 落到哪 |
|---|---|
| 大标题 / 标题大 / 字大 | `title_size` +16 |
| 标题小 / 小标题 | `title_size` -14 |
| 字距拉开 / 疏朗 / 呼吸感 | `letter_spacing` = 0.18em |
| 紧凑 / 紧密 | `letter_spacing` = 0.04em |
| 不要立绘 / 纯文字 / 别放立绘 | `show_characters` = false |
| 要立绘 / 带立绘 / 有立绘 | `show_characters` = true |
| 水墨 / 古风 / 毛笔 / 民国 | 标题字体 → 毛笔 |
| 冷峻 / 文学 / 印刷 / 书 | 标题字体 → 宋 |
| 科技 / 赛博 / 极简 / 现代 | 标题字体 → 黑体 |
| 圆角 / 柔和 / 治愈 | 圆角 10px |
| 直角 / 硬朗 / 锐利 | 圆角 0px |
| 暗 / 夜 / 冷 / 压抑 / 悬疑 | 深色主题 |
| 亮 / 清新 / 治愈 / 校园 | 浅色主题 |

明暗词一个都没有时，**跟着参考图的整体亮度走** —— 深色参考图配深色界面才不违和。

### `reference_images`

参考图的 **dataURL**（前端已经压到 1280 长边），最多 6 张。

**只用来取色和判断明暗，原图不落盘、不进成品。** 这是有意的：原图有版权，
而且写实照片当 UI 背景会和插画界面打架。

### `target`

- `both`（默认）：主界面 + 对话界面都出
- `title`：只要标题画面
- `dialog`：只要游戏内的对话框

### `base`

一般**不要传**。传了就强制从那套骨架出发，自动挑的能力就废了。
只有用户明确说「在 XX 那套的基础上改」时才用。

---

## 出来的是什么

一套**新预设** + 渲染好的 HTML。返回里有：

```
preset.id / name / vibe / base / palette / notes / file
screens[]     每块屏的 screen / relative / bytes
analysis      取到的参考图色、匹配到的预设、对比度、用了几张图
unsupported   听懂了但当前渲染层做不到的项
```

**关键点：设计只改参数，骨架仍是内置四套之一**（`preset.base` 指向它）。
标题位置、菜单排列、纸纹/光晕这些结构不变 —— 这就是六块界面不会散架的原因。

生成的新预设落在 `app/ui_presets/designed/<id>.json`，之后
**`render_ui` 也能直接用它**（`list_ui_presets` 里能看到）。

---

## 一定会有的「做不到」

**菜单排列（竖排 / 横排 / 编号）目前改不了。**

四套骨架的菜单排列是写死在 `render.py` 的 CSS 里的，`layout.menu` 这个参数
渲染时根本不读。所以：

- 用户说「菜单要编号」→ 返回的 `unsupported` 里会有 `菜单带编号`
- 你要**如实告诉用户「这项还没做」**，不许说「已经改成编号了」
- 不许手改渲染出来的 HTML 去硬凑 —— 下次重新渲染就没了

---

## 出图之后必须做

1. **自己打开看一眼**。配色对不对、标题读不读得清、有没有糊成一团。
   `design_ui` 只保证「参数合法、对比度 ≥ 4.5」，不保证「好看」。
2. **调 `check_ui`**。它查文件在不在、占位符替换干净没、强调色有没有真的套上。
3. **不满意就重调 `design_ui`**：换 `requirement` 的措辞，或换参考图。
   **不要**手改 HTML —— 那不是成品，下次渲染就覆盖了。

---

## 常见错

| 做法 | 为什么错 |
|---|---|
| 把用户的话总结成一句气质描述再传 | 具体的「大标题 / 字距 / 不要立绘」全丢了 |
| 参考图不传，自己描述颜色 | 取色是确定性的，描述是有歧义的，白白多一次返工 |
| 只给 `target=title` 却想交完整界面 | 对话界面没渲染，`check_ui` 会报还没渲染过 |
| 用户要的排列方式做不到，就含糊过去 | 用户以为改了，成品没变 —— 比不做更糟，`unsupported` 是给你说真话用的 |
