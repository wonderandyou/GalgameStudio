# 渲染：参数怎么给，坑在哪里

`render_ui` 只做一件事：把「预设 + 你给的文案」变成一张能打开的 HTML。
文案给错，出来的界面就是空壳 —— 这一篇讲怎么给。

---

## 一、启动页要给的参数

```json
{
  "preset": "ink-classic",
  "screen": "title",
  "title": "奇迹工坊",
  "subtitle": "WHALE FALL WORKSHOP",
  "menu": ["开始游戏", "继续游戏", "读取存档", "设置"],
  "version": "v0.1.0 build 2026.11"
}
```

| 参数 | 规矩 |
|---|---|
| `title` | 2~8 字最好。超过 10 字在竖排预设里会顶出画面 |
| `subtitle` | 英文，全大写。中文副标题在各套里都不好看 |
| `menu` | 4 项最稳；文案本身不超过 6 字（`开始游戏` ✓ `开始一段全新的旅程` ✗） |
| `version` | 放右下或底中，各套自动处理位置 |

**菜单文案要短。** 四个字的菜单项是 galgame 的通用写法：
`开始游戏 / 继续游戏 / 读取存档 / 设置`。
写成 `从第一幕重新开始` 会在竖排预设里变成两列。

---

## 二、游戏内界面

`dialog` / `choice` / `save` / `settings` / `hud` 五块，
**不需要文案参数** —— 工具会填示例内容，目的是让你看**皮的样子**，不是看内容。

真正接进游戏时，台词的文字由播放器渲染，这里只验证：
- 底板够不够挡住复杂背景
- 文字和底板的对比够不够
- 元素位置有没有压到立绘

**所以要连着背景一起渲**（传 `bg`），纯色底看不出问题。
底板半透明＋复杂背景 → 才能发现「字读不清」这类真问题。

---

## 三、背景图怎么来

1. **优先自己传**：`bg: "assets/bg/tenshou_rain.png"`（项目相对路径即可）
2. **不传时自动挑**：工具扫 `assets/bg/` 下第一张 **>20KB** 的 png
   - 会跳过 mock 占位图（那种只有 157 字节）
   - 挑不到就出无背景版 → **这时要如实说「项目里还没有可用背景图」**
3. **立绘只有 `ink-classic` 用**：
   `char_left` / `char_right` 会自动从 `assets/char/` 挑；
   其他三套传入会被忽略（设计如此）

## 四、五个真坑

### 1. 竖排预设里标题超过 8 字会顶出画面
水墨和剧场的标题是**竖着排**的。8 个汉字在 74px 下已经占到画面高度 60%。
超过 10 字必然溢出。**遇到长标题先缩字号，不要硬塞。**

### 2. 深色预设配浅色背景 = 字看不见
`cinema-dark` 会把背景压到 `brightness(.74)`，`theater-cold` 压到 `.34`。
如果传的背景本身就是浅色的（比如雪景、白天校园），压完还是偏亮，
白色标题就糊了。**深色预设要用深背景图。**

### 3. `paper-indie` 的右下角按钮压在图上
它的右下角齿轮/关闭在斜切配图区（深色）上，
所以按钮用了白色 + 阴影。**如果传的背景很亮，这两个按钮会看不清** ——
这时要么换背景，要么改用 `cinema-dark`。

### 4. 微调后必须重新渲染
`tweak_ui_preset` 只改状态，**不产出文件**。
改完不重新 `render_ui`，看到的还是上一版。

### 5. HTML 路径是项目相对的
返回的 `path` 在项目的 `ui/rendered/` 下。
要打开它得知道项目根目录 —— 别把相对路径直接当系统路径用。

---

## 五、渲染完的自检动作

工具返回 `ok` **只代表文件写出来了**。还要：

1. 打开 HTML（或截图）看一眼
2. 确认：标题完整没被裁、菜单没折行、背景加载了、字看得清
3. 再调 `check_ui` 做机器检查

两者都过，才算这块界面能交给用户看。
