# 连贯性：摘要、伏笔、角色一致

上千节点的作品，最容易死在「写到第 40 章时忘了第 5 章说过什么」。
这不是记忆力问题，是**上下文预算**问题 —— 你看不到全文，只能靠摘要。

所以连贯性是一套**记录制度**，不是靠天赋。

---

## 一、摘要怎么写

`finish_chapter` 的 `summary` 是后面所有章节唯一能看到的东西。写砸了，
第 40 章就会写出一个已经死掉的角色。

3~5 句，200 字以内，按这个顺序写：

```
1. 这一章发生了什么（事实，不是感受）
2. 谁的什么变了（关系、状态、知道了什么）
3. 留下了什么没解决（钩子，下一章要接的）
```

### 好的摘要

```
女主终于说出两年前离开的原因：她母亲病了，她一个人扛。
男主的反应是沉默，没有责怪也没有安慰，两个人第一次一起沉默了很久。
现在他们都知道这件事摊开了，但谁也没提接下来怎么办。
埋下：男主口袋里那张已经作废的车票。
```

### 坏的摘要

```
✗ 这一章感情描写很细腻，两人在雨里谈了心，气氛很好。
   （没有事实，下一章接不上）
✗ 第 12 到 16 个节点，男主去天台见了女主，聊了两年前的事。
   （只有流程没有内容）
```

**判据**：如果只读摘要，能不能接着写出下一章的第一句台词？能，就是合格。

## 二、伏笔怎么管

一部作品埋 5~8 个伏笔就够了，多了收不回来。

每个伏笔在埋的时候，就在摘要里记下三件事：

| 记什么 | 例子 |
|---|---|
| 物件/信息是什么 | 作废的车票 |
| 埋在第几章 | c05 |
| 准备在哪里收 | c42（她看到他箱子里还留着） |

**收线比例硬要求**：埋了 6 个，至少要收 4 个。
剩下 2 个可以不收（留白），但**不许埋了 10 个一个都不收** ——
玩家会觉得被耍。

### 常见的坏伏笔

- 埋的时候太用力（描写了三次那个盒子），玩家提前猜到了，收的时候没有惊喜
- 埋得太轻，收的时候玩家完全不记得，效果归零
- 收了但不解释，玩家一脸问号

正确力度：**埋的时候用一句普通的台词带过，收的时候让读者「啊」一声。**

## 三、角色一致性

### 外形锚点（第一次就要定死）

`upsert_character` 有两个字段，分工不同：

| 字段 | 给谁用 | 写什么 |
|---|---|---|
| `note` | 编剧自己 | 说话方式、口头禅、禁忌 |
| `look` | **美术生图** | **发色发型 + 眼睛 + 常服 + 体型身高 + 年龄气质**，五样都要有 |

`look` 是**立绘的唯一依据**：美术会把这句话逐字复用到每一张立绘的提示词里。
留空的话，同一个角色每次生图都会变一个人。

**只写名词和数字，不写形容词。** `漂亮`/`可爱`/`唯美` 这类词每次画出来都不一样，等于没写。

```
✓ look: "黑色短发齐耳，深褐瞳单眼皮，米色风衣，身高约170cm偏瘦，
        二十出头，左耳一颗小痣"
✗ look: "好看的女生"（不是外形描述，等于没写）
✗ look: "一个漂亮的黑长直女孩"（形容词，每张都长得不一样）
```

用户没传参考图时，这四个维度**由你从需求里定**；定完就锁死，
后续任何地方都不许改写（详见 `art/08-no-reference.md`）。

第一次 `upsert_character` 就要把 `look` 写全，之后不要改 ——
改一次，之前所有立绘都得重画。

### 说话方式

每个角色的说话方式在 `upsert_character` 的 `note` 里定死，后面必须照做：

```
note: "话少 / 口头禅「随便」 / 从不提她父亲"
```

三个问题自检：

- [ ] 把名字遮住，能认出这是谁在说话吗？
- [ ] 有没有写出跟 `note` 矛盾的话？
- [ ] 这个角色在紧张时、开心时的说话方式有区别，但**核心腔调不变**吗？

### 关系变化要留痕

角色之间的关系不能凭空变化。每一次关系变化，都要有一个**可指认的节点**：

```
✗ 第 20 章还很疏远，第 21 章突然很亲密（中间没写任何转折）
✓ 第 21 章 c04-s08 她说了一句「你陪我一会儿」，关系从这里开始变
```

在摘要里记下：「关系从 X 变成 Y，转折点是 c04-s08」。

## 四、时间线与地点

长作品必然会有时间跨度，要能自己核对：

| 项 | 记在哪 |
|---|---|
| 故事发生在几天内 | 大纲的 logline 里定死 |
| 每一章的时间 | 章标题里体现（如「第二天·清晨」） |
| 地点转移 | 同一地点**同一时段、同一天气**才用同一个 `bg_key`；换了时段/天气/状态就是新键 |

**同一天内发生的事，不要写成两个季节。** 写到第 50 章时，
回头核对一下前面写的天气和季节对不对 —— 这个错误玩家一定会发现。

## 五、复用而不是重写

上千节点的作品必须大量复用，否则写不完：

| 复用什么 | 怎么复用 |
|---|---|
| 背景 | 同一个**地点 + 时段 + 天气**才复用同一个 `bg_key`。同一个地方换到夜里、下起雨、或者变成空无一人的废墟，都是**新的键** —— 观众记住的是变化，不是同一个角度重复三十次 |
| 立绘 | 同一角色**同一情绪**才复用同一个 `pose`。「平静」和「强忍眼泪」不是一张图 |
| 场景描写 | 回到同一个地方时，用一句「还是那个样子」带过，不要重新描写 |
| 日常对话 | 允许重复的日常节奏（起床、吃饭），但每次要带一点新信息 |

**复用不是偷懒，是长篇的必要结构。** 读者也需要熟悉的场景来定位。
但**复用的是「地方」，不是「画面」** —— 地方不变、光线和人的状态要变。

## 五·B、背景与立绘的丰富度配额

一条长链只用一个背景、一个表情，读起来像在看幻灯片。硬性下限：

| 项 | 下限 | 怎么做到 |
|---|---|---|
| 每章不同的 `bg_key` | **2~4 个** | 一章 15 个节点，至少要换 2 次景 |
| 全书主要地点 | **8~20 个** | 别在天台上把 30 章全写完 |
| 同一地点的时间/天气/状态变体 | **1~3 个** | 白天→夜、晴→雨、有人→空了、整齐→狼藉 |
| 每个主要角色的立绘姿态 | **5~8 种** | 平静、惊讶、难过、笑、低头、背对、转身要走… |
| 同一角色连续同一个 `pose` 的节点 | **≤ 5 个** | 超过就该换个表情了 |

判断换不换景，就问一句：**这一段如果拍成动画，镜头会不会切？** 会切，就该有新图。

姿态写具体动作，不要只写情绪词：

```
✓ pose: "低头看手里的票，指节发白"
✓ pose: "背对门口站着，肩膀绷着"
✗ pose: "难过"        ← 美术不知道怎么画
✗ pose: "正常"        ← 等于没写
```

## 六、每 5 章的连贯性自检

| 检查 | 期望 |
|---|---|
| 摘要里有没有「谁的什么变了」 | 每章都有 |
| 埋的伏笔是否记了章号 | 全部记了 |
| 角色说话方式有没有走样 | 遮住名字能认出 |
| 时间线有没有矛盾 | 逐章对一遍 |
| `bg_key` 有没有重复生图的情况 | 同一场景只有一个键 |

这五项每次自检都跑一遍，成本很低，能挡住绝大多数崩坏。
