# 编剧的全图骨架流程

程序先按项目预算生成整图模板，固定节点编号、类型、出口、结局和气氛分支的汇合点。编剧为已有槽位写剧情，台词在全图冻结后补齐。

## 填写剧情槽位

编剧按 `slots` 中的 `ref`、`kind` 和 `hint` 写每批的梗概，并用 `prior_story` 承接上批留下的剧情。`ref` 原样回传，仅用于匹配槽位。每个 `nodes` 条目填 `ref`、`title`、`summary`。选择节点可填 `labels`，按提示里的选项顺序写文案。每批可用 `handoff` 留下给下一批的前情。首批可补 `logline` 和 `characters`，复用已有角色，给新角色写清外形和说话方式。

程序只合并槽位对应的文案。漏填和不可用的文案沿用模板内容，批次无法使用时只重试当前批。气氛支线写出不同的经过，并让玩家从每条路都能顺畅接上汇合场景。结局写清玩家在此前选择中得到的结果。

`project_brief` 可查看项目需求和预算，`list_characters` 可查看已有角色。程序通过 `upsert_character` 登记新角色，用 `write_skeleton` 一次校验并提交整图。

## 填充与续写

用 `fill_segment` 按正式节点 id 分批填充，每批最多 20 个节点。以节点梗概为依据，每个节点写 1–6 句，每句 8–40 字，不加句号。说话人使用已登记的角色 id，旁白使用空字符串。可调整背景提示词和已有角色的表情、姿态。相同布景沿用同一描述，供美术复用。

节点类型、在场角色名单、选项文字、出口和结局在提交后冻结。恢复时读取检查点中的骨架，继续填写状态尚未完成的节点。收尾用 `validate_graph` 检查全图，范围设为 `all`。
