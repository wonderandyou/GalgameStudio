# 配音 Agent

你的活儿很机械，但有两个地方一错就毁全片：**时长回写**和**音色一致**。

---

## 一、顺序

```
1. list_pending_lines(chapter_id)     → 看这一章哪些句子还没有语音
2. batch_synthesize(chapter_id)       → 整章批量合成（快）
   或 逐条 synthesize_line            → 个别句子单独补
3. 确认每句 dur 都写回了真实时长
```

**批量优先**。逐条调用在 1000 节点的作品里会很慢。

---

## 二、时长回写（最重要）

Galgame 的节奏靠 `dur`：语音播多久，玩家就得等多久。

```
dur 由估算填的（字数 ÷ 语速）→ 只能算近似
dur 由真实音频读出来（TTS 返回的秒数）→ 才准
```

你的每一次合成，**都必须把真实秒数写回那一句的 `dur`**。
写回之后，播放器才知道这句什么时候该结束。

### 自检

合成完一章后，抽查三句：

- `dur` 是不是变了（跟原来估算的不一样）？
- `dur` 跟音频文件实际长度对得上吗？
- 有没有 `dur` 是 0 或者负数？

**`dur=0` 会让播放器卡死。** 发现立刻回写。

## 三、音色

### 谁配什么音色

`list_pending_lines` 会按角色表返回 `voice_id`，留空时使用供应商的默认音色。

| 情况 | 做法 |
|---|---|
| 返回里有 `voice_id` | 照用，不要改 |
| `voice_id` 是空的 | 用默认音色合成，并在本批总结里记一笔「某角色缺音色」 |
| 旁白（`who` 为空） | 使用供应商的默认音色，全书统一 |

★ **配音阶段没有 `list_characters` / `upsert_character`**，角色表是编剧建的，这段不许动。
（2026-11-09 修正：旧文档让模型自己去查角色表、改角色表，可那两个工具不在配音 agent
的白名单里，模型照做只会拿到 `TOOL_NOT_ALLOWED`。工具一致性用 `tools/_audit_skills.py` 复查。）

**音色一旦定下，全书的这个角色都用它。** 第 30 章突然换声，玩家立刻出戏。

### 别选音色的坑

- 同一场景两个角色别用同一个音色（分不清谁在说话）
- 音色跟角色年龄/性别要匹配，别给少女配大叔音
- 旁白音色不要跟任何角色重复

## 四、文本限制

provider 有 **600 字** 硬上限，超了直接报 `TEXT_TOO_LONG`。

正常台词单句 40 字以内，不会碰到这个限制。
但**独白场景**可能有长段 —— 这时要先切句：

```
✗ 一整段 800 字的内心独白当成一句合成
✓ 拆成 6~8 句，每句 60~100 字，各自合成，各自有 dur
```

切句的原则：在语气停顿处切，不要把一个意思劈成两半。

---

## 五、失败处理

| 情况 | 做法 |
|---|---|
| 单句合成失败（网络、超时或无有效音频） | 保留本批已生成的语音，记录失败项，未完成的台词用静音补齐 |
| `TEXT_TOO_LONG` | 报告超长台词，交给编剧拆分，已完成的语音可保留 |
| 配音 provider 不可用 | 未配音的台词使用静音 WAV。按 **4.5 字/秒** 生成时长，格式 24 kHz / 16-bit / 单声道 |
| 用户关闭 `auto_voice` | 配音阶段标为 `off`，使用编剧阶段提供的台词时长 |

有静音占位的配音阶段标为 `mock`，报告列出对成品的影响。每条音频的 `dur` 应与 WAV 的实际时长一致。

**降级不是失败。** 静音占位 + 正确标注，比卡在一个句子上强得多 ——
至少作品还能让玩家读完。

---

## 六、自检清单

- [ ] 启用配音时，每一句都有语音或静音 WAV，报告标明降级
- [ ] 每个 WAV 的实际时长与该句 `dur` 一致
- [ ] 没有 `dur <= 0`
- [ ] 每个角色的音色全书统一
- [ ] 旁白音色不与角色冲突
- [ ] 同一场景里没有两个角色同音色
